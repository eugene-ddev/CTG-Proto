# Cuber The Game — браузерный прототип

Phaser 4 + TypeScript + Vite. С версии 1.0.0 — сетевой: прогресс хранится на сервере `CTG-Proto-Backend` (Nakama),
без запущенного сервера в игру не войти. Данные игры — локальные JSON-конфиги (общие с сервером).
Версия — `package.json` (`version`), показывается в меню («ПРОТОТИП · ВЕРСИЯ x.y.z»); поднимается с каждым обновлением.

План по этапам: «CTG — прототип на Phaser: план» в проекте Cuber The Game.

## Где что лежит

| --- | --- |
| `F:\Projects\games\CTG-Proto` | этот прототип |
| `F:\Projects\games\CTG` | Unity-клиент (источник чертежей, префабов, Sandbox-ассетов) |

## Сеть (с 1.0.0)

План по этапам — `CTG-Backend/docs/network.md`.

- Сначала сервер: в `F:\Projects\games\CTG-Proto-Backend` — `npm run up` (Docker). Потом `npm run dev` здесь.
- Вход (`scenes/LoginScene.ts`): новый игрок вводит имя (уникальное, 3–16 символов); дальше браузер входит сам по
  device id из localStorage. «Сменить игрока» — в панели DEBUG (вход забывается, аккаунт на сервере остаётся).
- `net/client.ts` — клиент Nakama. Адрес сервера: `?server=host:port` в адресе страницы, иначе `VITE_NAKAMA_HOST` /
  `VITE_NAKAMA_PORT` / `VITE_NAKAMA_SSL`, иначе у выложенной сборки — домен самой страницы, иначе `127.0.0.1:7450`. `?profile=имя` — отдельный игрок в том же браузере
  (две вкладки с разными профилями — два игрока).
- **Действия** (с 1.1.0): состояние меняется только через `store.act('имя', ...аргументы)`; список действий —
  `core/actions.ts` (общий с сервером). Действие исполняется сразу в браузере и уходит на сервер пачкой
  (`player/act`), сервер исполняет его сам над состоянием из базы и возвращает отпечаток итога. Отклонил или итог
  другой — берётся состояние сервера. Новое изменение состояния = новая строка в `ACTIONS`, сцены состояние
  напрямую не трогают. Время и случайность внутри действия — из `ctx` (`core/clock.ts`), не `Date.now()`.
- **Бой серии** (с 1.2.0) считает сервер. Противника (`startRun`) и зерно боя (`startFight`) выбирает он —
  эти действия идут через `store.request` (клиент ждёт ответ и берёт состояние сервера, экран «Подбор
  противника…»). Сцена боя строит бой из состояния (`core/fight.ts → createRunBattle`) и в конце отправляет не
  итог, а ввод игрока — когда нажаты артефакты и на каком ходу он сдался; сервер пересчитывает бой тем же кодом
  (`resolveFight`). Лут побеждённого лежит в состоянии (`state.loot`) и забирается действием `lootTake`.
- **Два вида серий** (с 1.3.0), кнопки на главной:
  - «С ботами» — как раньше, но при поражении всё остаётся у бойца (`arena.json → loss.bots = keep`).
  - «С игроками» — экран «Соперники» (`scenes/RivalsScene.ts`): список игроков с рейтингом и «+N за победу /
    −M за поражение»; «Вызвать» фиксирует на сервере снимок активного бойца соперника (`arena/challenge`), дальше
    обычные экран противника и бой. Повторов нет; победа — лут соперника (копии) и рейтинг, поражение — оружие и
    рюкзак пропадают (`loss.players = drop`), соперник получает награду. После победы соперник следующего боя
    выбирается заново. Рейтинг — Эло (`core/rating.ts`), изменение у защитника обратное.
  - «Пока тебя не было» на главной — журнал нападений; закрытие окна забирает награды за отбитые нападения
    (`arena/claimInbox`).
  - Рейтинг, счёт и журнал — не в состоянии игрока, а в отдельной записи на сервере (`store.arena`,
    тип `ArenaProfile`): чужие бои состояние игрока не трогают.
- Вкладка **«Рейтинг»** (с 1.4.0, `scenes/LeaderboardScene.ts`): таблица лидеров — место, игрок, рейтинг, победы и
  поражения; своя строка выделена, место и число игроков — в заголовке. Данные — `arena/leaderboard`.
- Справа внизу — «сохранение…» / «нет связи с сервером». Игра в двух вкладках одним игроком: побеждает сервер.
- Таймеры на экране считаются по часам сервера (`store.now()`).
- Отладка (панель DEBUG): кубы, предметы, лечение и сброс работают, пока сервер в режиме отладки
  (`CTG_DEBUG=true` в `local.yml`); лимит повторов серии при игре через сервер берётся из конфига.
- Правила общие с сервером: после правок в `src/core` или `src/data` — в `CTG-Proto-Backend` выполнить
  `npm run sync-core` и `npm run up`, а `npm run dev` перезапустить (отпечаток логики считается при старте).
  Иначе при входе будет «Правила на клиенте и сервере разные» (`tools/core-digest.mjs`).
- Тесты и `npm run sim` сервер не требуют.

## Навигация

- Клик мимо модального окна закрывает его. Отпускание после жеста поворота модели не считается кликом (`src/ui/dragGuard.ts`).

- Инвентарь показывает только то, что лежит в инвентаре; надетое и содержимое рюкзаков — в «Персонажах». В списке персонажей превью целиком, у бойца с разбитыми кубами — значок ремонта (зелёный и качается — чинится в лобби, красный — боец в серии арены).

- Меню → Инвентарь, Чертежи, Крафт, Персонажи; «Арена» открывает выбор персонажа.
- Чертежи → «Крафт» открывает крафт сразу с этим чертежом; «Назад» возвращает к списку.
- ESC — назад (или закрыть модалку). Ссылка «UI-кит» внизу меню — витрина компонентов.
- В консоли браузера доступен `__game` (экземпляр Phaser.Game) для отладки.

## Рендер моделей (этап 2)

- `src/render/iso.ts` — чистая математика без Phaser: блоки чертежа → видимые грани в экранных координатах, от дальних к ближним. Оси и эйлеры как в Unity (`Quaternion.Euler`: Z, потом X, потом Y), камера — изометрия 45° по горизонтали и 30° сверху.
- Формы сняты с FBX клиента: куб 1×1×1 и клин (`TriangleLowPoly`) — призма вдоль X, целые грани верх и задняя, наклон снизу. Если клинья окажутся развёрнуты не туда, переключи `WEDGE_FLIP_Z`.
- Грань, вплотную закрытая целой гранью соседа, не рисуется.
- `src/ui/VoxelView.ts` — компонент: вписывание в рамку, поворот на 90° с анимацией, подсветка блока под курсором (события `blockover` / `blockout` / `blockclick`), цвет блока через `colorOf`, вид `lookOf` (обычный, силуэт, скрыт — для крафта), маркеры слотов.
- Сцена «Модели» (ссылка внизу меню): все 15 чертежей, поворот ← → или Q / E, данные блока под курсором, демо-раскраска персонажей по статам.

## Крафт (этап 5)

- `src/core/craft.ts` — логика: результат чертежа (модель персонажа или предмет, у камня и флаконов — по выбранному варианту), списание кубов целиком в конце сборки, «Автосборка» после первой ручной сборки, разборка за половину кубов (вниз).
- `src/core/build.ts` — порядок сборки: старт с самого нижнего куба, дальше слоями снизу вверх — доступны блоки нижнего недостроенного слоя, примыкающие к поставленным. Выше ничего не стоит, поэтому верх каждого доступного блока виден камерой (центр камня, блоки под панцирем лобстера не замуровываются). Автосборка идёт тем же порядком.
- `src/core/stats.ts` — распределение кубов персонажа по статам: дефолт пропорционально базовым статам чертежа, `nextStat` выбирает стату для следующего куба (кисть, пока у неё есть квота).
- Сцена крафта: сборка начинается с одного куба; видны только поставленные кубы и прилегающие к ним (полупрозрачные), остальное скрыто — недостижимых кубов нет. Поставленные блоки — в цветах будущего предмета.
- Персонаж: над моделью палитра «Цвет куба» — «Авто» (по умолчанию) и 6 цветов статов:
  - «Авто» — цвет берётся из ползунков панели «Статы» (сумма = числу кубов): каждый куб — стата, у которой ещё остались кубы. Пока не всё распределено, достроить и запустить автосборку нельзя;
  - выбранный цвет — куб ставится им, ползунки подстраиваются сами (сперва из нераспределённых, потом у статы с наибольшим запасом); клик по поставленному кубу перекрашивает его. Повторный клик по цвету — снова «Авто».
  Ползунки двигаются в обоих случаях; уже поставленные кубы уменьшить нельзя.
- Недостроенная часть модели видна еле заметным контуром — понятно, какой будет фигура; нажать на него нельзя.
  Итог хранится у персонажа (`blockStats`).
- Камень и флаконы: выбор стихии / статы и под ним описание, что делает выбранный вариант (эффект камня: урон, длительность, стаки; зелье: сколько кубов чинит).
- Пустые места подсвечены и пульсируют, контур пунктирный. У предметов подсветка синяя, у персонажа — цвета статы, которой встанет следующий куб.
- Поворот: жест (потянуть модель по горизонтали, мышью или пальцем — по отпусканию доворачивается до 90°), стрелки внизу, ← → / Q E. Жест работает и в окне «Модели». Выйти посередине — бесплатно.
- Старые сейвы подтягиваются к конфигам: новые чертежи открываются, предметы и модели удалённых чертежей убираются (`migrate` в `src/game/store.ts`).
- Если сборку нельзя завершить (не хватает кубов, у куба нет статы), появляется окно с причиной, кубы не тратятся.
- Разборка: в инвентаре (кнопка в панели предмета, с подтверждением) и для моделей в окне «Персонажи».

- Автосборка: количество «− N +» — собирается одна модель, в инвентарь падает N штук (N × стоимость кубов). Ручная сборка — всегда одна. Количество запоминается по чертежу.
- Закрыть окно «Готово» крестиком или ESC — сразу новая сборка того же чертежа (можно сменить вариант).

## Персонажи (этап 6)

- Персонаж появляется сразу после крафта по чертежу: имя по умолчанию («Лобстер 1»), слоты пустые. Отдельного списка моделей и шага «сборки» нет; старые сейвы с моделями превращаются в персонажей (`migrate`).
- `src/core/character.ts` — логика без Phaser:
  - статы как в Sandbox Arena клиента (`SandboxStats`): базовая стата чертежа + 1 за куб; стамина = Выносливость, мана = Интеллект; разбитый куб −1 (`Stats.AdjustStats`);
  - крит/уворот: score = 0.8·Удача + 0.2·Сила (Ловкость), шанс = 0.75·score / (60 + score);
  - регенерация +2 стамины и маны за свой ход; броня режет A / (A + 50), не больше 85%;
  - урон слота: Base · (1 + 3·(0.7·стата/100 + 0.3·ур./20)) · Condition; скалируют только Сила и Ловкость;
  - слоты: руки и артефакты из чертежа + рюкзак; подсумок не надевается; требование к скалирующей стате;
  - `equip`/`unequip` (замена возвращает старое в инвентарь), `renameCharacter`, `disassembleCharacter` (половина живых кубов, снаряжение в инвентарь).
- Окно «Персонажи»: слева список и «+ Новый персонаж» (ведёт в «Чертежи» на вкладку персонажей), справа карточка выбранного: перетаскивание из ленты инвентаря в слот (подсвечиваются подходящие) или клик — в первый подходящий слот; клик по надетому или перетаскивание мимо слотов — снять; имя печатается с клавиатуры и сохраняется по Enter / клику мимо.
- Панель стат пересчитывается на лету: кубы и очки по статам, крит, уворот, стамина, мана, броня, урон и урон за ход по каждой руке; красным — если не хватит стамины или маны.
- Поле ввода — `src/ui/TextField.ts` (Phaser, без DOM): на телефоне экранная клавиатура пока не открывается.

## Снаряжение и рюкзак

- Клик по ячейке персонажа открывает окно выбора: подходящие по типу предметы из инвентаря и «Снять».
- Надетый рюкзак добавляет 6 ячеек для зелий (`putInBag` / `takeFromBag`); при снятии рюкзака или разборке персонажа содержимое возвращается в инвентарь.
- Инвентарь показывает и надетое («на Лобстер 1»), и содержимое рюкзаков («в рюкз. Лобстер 1»).
- «Изменить персонажа» (0.0.50): вид сборки по чертежу с кубами бойца — перекрасить, убрать, поставить (кистью или ползунками); 1 куб за каждый изменённый куб, списывается при подтверждении (`core/edit.ts`, режим `editCharUid` в `CraftScene`).
- Экран персонажа (0.0.51): модель без поворота; 5 ячеек пресетов (`presetsOf` / `savePreset` / `clearPreset` / `applyPreset` со слотом); правая колонка — сведения о бойце или карточка выбранного предмета (`ui/itemInfo.ts`, прокрутка — `ui/ScrollArea.ts`).
- Схема удара кубами (0.0.62): `core/spread.ts` (`spreadCells` — куда уходит остаток, по правилам `applyOverflow`), `ui/SpreadView.ts`; в тултипах оружия, в блоке «Прокачка» карточки и в тултипе под Alt.

## Арена и бой (этап 7)

- Логика — перенос клиента Unity (`src/core/battle.ts`): `ArenaBattleProcessor` (игрок первый, лимит 200 ходов — победа по живым кубам, ничья игроку), `Character.BeginTurn` (эффекты → кулдауны → +2/+2), `Abilities.AutoUse` (руки по порядку, вторая — пока первая в откате; артефакты — вручную), `AttackAbility` (урон по формуле — фиксированный, без разброса min–max; крит ×2), `Character.TakeDamage` (щит → уворот → броня, крит её игнорирует), `Block` (прочность 10, остаток делится между живыми соседями из 26), эффекты горение/яд/щит (повтор — обновление длительности).
- Шансы (крит, уворот, распространение горения) — марбл-бэги (`src/core/bag.ts`): при шансе 10% ровно 1 срабатывание на каждые 10 попыток; размер мешка — `combat.json → bagSize`. Подробно — `CTG-Backend/docs/battle-rework.md`.
- Пороги стат (`combat.json → statThresholds`): разбито больше половины кубов статы — её функция отключается (Сила — силовое оружие ×0.6, Ловкость — уворот, Удача — крит, Выносливость — реген 1.5, Интеллект — артефакты). Надпись над моделью, иконки состояния под барами, строка «до отключения» на экране противника.
- Цель удара — раскопка: только передний живой куб столбика (+Z), столбик — по кратчайшему пути к первой стате приоритета; остаток урона уходит в следующий куб раскопки. На экране противника — золотая полоса через все кубы в порядке разбития и золотая обводка кубов статы при наведении на плашку приоритета.
- Схемы ударов оружия (`items.json → pattern`): точный (кинжал, нож), рубящий (меч), колющий (копьё), раскалывающий (топор), дробящий (булава, молот); кинжал бьёт 2 раза за ход. Числа баланса поверх Unity — `tools/build-config.py → BALANCE`.
- Раскладка стат слоями спереди назад (`core/layout.ts`): автосборка — `combat.json → layout.autoBuild`, боты — один из `layout.bots`; приоритет бота — под сборку игрока (`botTarget`). Золотой треугольник у пола перед моделью (куда смотрит перёд) — в сборке, у персонажа и на экране противника.
- Мешки вне боя (`PlayerState.bags`): награда за серию и генерация ботов; бот выбирается один раз при фиксации противника, броски записываются в серию и повторяются на экранах.
- Баланс — `npm run sim`: матрицы побед «оружие × оружие», «приоритет × приоритет», отчёт в `tools/sim/report.md`.
- Случайность — только через seed (`src/core/rng.ts`, порядок шариков в мешках): один seed — один исход и тот же лог (тест).
- Противники — боты из `src/data/config/opponents.json` (`generateOpponent` в `src/core/opponent.ts`):
  - чертёж той же категории, что у бойца игрока (кубов столько же);
  - уровень оружия (1–3) = лучшее оружие игрока в руках или ниже на `weaponLevelSpread` (2); ячеек камней 0…(уровень − 1), не больше 3;
  - главная стата — Сила или Ловкость, в руках только оружие этой статы, она самая большая, вторая стата оружия не качается;
  - артефакт (`artifactChance`) с маной — только вместе с кубами Интеллекта на `manaCastsReserve` применений; без артефакта Интеллекта нет;
  - рюкзак (`rucksackChance`): зелья под свои статы и иногда запасное оружие главной статы;
  - пресеты Sandbox Arena (Mega Lobster, Waran, Strength Waran) остались в `OPPONENT_PRESETS` для тестов.
- Пустая рука бьёт кулаком 1–3 (базовая атака персонажей Sandbox); в клиенте без оружия урон сейчас 0.
- Экраны: «Арена» в меню → выбор бойца (по умолчанию последний) → «Новый противник» (карточки бойцов, приоритет атаки — сохраняется у персонажа) → бой. Бойца и противника до боя не сменить: противник выбирается при входе в серию и после каждой победы и хранится в `arenaRun.opp`.
- Бой: полоски КБ/ВН/МН, слоты с кулдаунами, всплывающий урон, лог; артефакт — клик по слоту или пробел (нажатый перед своим ходом срабатывает сразу после него, чтобы щит закрыл ход противника); ESC — пауза («Сдаться»), скорость ×1/×2.
- Раскладка боя: имена и компактные полоски в шапке, слоты обоих бойцов внизу по центру через черту, короткий лог слева снизу, все кнопки (продолжить, скорость, сдаться, выйти) — в меню-бургере справа сверху (или ESC).
- Попадание: сплэш в точке удара (крит — крупнее, золотой), осколки цвета куба; разбитый куб разлетается сильнее.
- Полоса целей у обоих бойцов (под полосками): сегмент на каждую стату бойца в порядке атаки соперника, ширина — доля кубов, заливка — живые; целевой сегмент — золотая рамка и стрелка.
- Индикатор хода («ХОДИТ» и золотое имя), подсветка слота, которым бьют в этом ходу; пропуск хода — пауза 2 с; «Выйти» — с подтверждением (засчитывается поражением).
- Оружие и артефакты на модели («Новый противник» — неподвижно, бой — с анимацией; на экране персонажа их нет): по слотам чертежа клиента — позиция, масштаб слота (0.8), масштаб корня префаба (щит 0.5), зеркало для левой руки (`src/render/anim.ts`, `placeItem`). Артефакты стоят ровно, без наклона оружия.
- Бойцы повёрнуты друг к другу по диагонали изометрии (yaw 180° / 270°); свой боец слева.
- «Новый противник»: карточки бойцов (свой слева), приоритет атаки — горизонтальные плашки, порядок меняется перетаскиванием.
- Анимации из клиента (кость Root), в прототипе медленнее (удар 1.25 с, ход 1.5 с на ×1): покачивание `Idle.anim`, удар `SwordAttack.anim` (у всего оружия; `DaggerAttack.anim` перенесён, но не используется), выпад тела `CharacterAttack.anim`, уворот `CharacterEvade.anim`. Урон всплывает в момент попадания (`DispatchAttackHit`). Срабатывание артефакта — подъём, увеличение, вспышка и кольца (в клиенте своей анимации нет).
- 3D-бой (`src/render3d`): блоки — меши и материалы клиента из `CTG/Assets/Resources/Models` (`render3d/blocks.ts`). Куб и клин `CubeLowPoly` / `TriangleLowPoly` с шипом сверху; материалы — как URP Lit клиента: цвета `Materials/Cube|Triangle/*Material` (стата → Black / Red / Yellow / Blue / Green / Orange, дерево → Brown, металл → White), гладкость 0.7 у куба, у клина 1 (в прототипе шероховатость 0.12, чтобы блик читался), карта нормалей (у куба ×2) и затенение по `Cube_HeightMap`; отражения окружения — `RoomEnvironment` с силой `ENV_INTENSITY` в `Arena3D.ts`. Разлетающиеся целые кубы — тот же меш. Пересборка из клиента: `node tools/unity-export/blocks.mjs` и `python3 tools/unity-export/block_maps.py`.
- 3D-превью моделей (0.0.108): главная, «Персонаж», сборка чертежа и «Новый противник» рисуются в three.js — `ui/VoxelView3D.ts` с тем же API, что у `VoxelView` (вид блоков, обводки, кольцо починки, наведение и клик лучом, поворот жестом, треугольник «перёд»), выбор — `ui/modelView.ts` (без WebGL — прежняя 2D-изометрия). Камера ортографическая под углом изометрии, рамка — `fitModel` (общая с 2D). Все превью рисует один WebGL-контекст (`render3d/preview.ts`) в свои текстуры Phaser, кадр в 2× (`RES`), перерисовка — только при изменениях (и пока пульсируют пустые места / идёт починка). Список бойцов, «Чертежи», иконки предметов и «Модели» — пока 2D.

## Навигация

- Вверху каждого экрана (кроме боя) — табы: Меню, Инвентарь, Чертежи, Персонажи, Арена (`BaseScene.navTabs`, `setupScreen({ tab })`). Из крафта вкладка «Чертежи» ведёт к списку чертежей.
- «Арена»: после первой победы в серии — продолжить серию; иначе — выбор бойца. До первой победы бойца можно сменить и переодеть, после — снаряжение только из рюкзака.

## Серия арены и лут (этап 8)

- Логика — `src/core/arena.ts` (тесты `arena.test.ts`), по табу «Арена» доки бэкенда: press-your-luck.
- «Арена» в меню начинает серию с выбранным бойцом; пока серия идёт, кнопка продолжает её («Арена · бой N»).
- Победа: осколки = число разбитых кубов противника (копятся в серии), лут не падает сам: в окне победы видны ячейки врага (оружие и артефакты с их уровнем, содержимое рюкзака, осколки разбитых кубов) — перетаскиваешь в свой рюкзак (или клик — в первую подходящую ячейку), сколько влезет; незабранное пропадает при уходе с экрана; нет рюкзака или места — лут не забран. Дальше — «Забрать и выйти» (осколки в кошелёк) или «Следующий бой».
- Поражение (в том числе сдача, выход посреди боя, перезагрузка страницы во время боя): пропадают оружие в руках и рюкзак со всем содержимым, осколки серии сгорают; артефакты остаются.
- Разбитые кубы сохраняются между боями серии; чинятся только зельем из рюкзака. В лобби — сами, по одному кубу за 30 с (`LOBBY_REGEN_MS`), зельем — сразу. На экране персонажа разбитые кубы — силуэты цвета своей статы, у чинящегося сейчас — обводка и кольцо прогресса.
- Зелья в лобби — из инвентаря или рюкзака бойца (`drinkPotion`), в серии — только из рюкзака. Клик по разбитому кубу в «Персонажах» — окно с зельями его статы (кликнутый куб чинится первым) или крафт малого/большого флакона этой статы. В окнах выбора предмета — кнопка «К чертежам» на нужную вкладку. Клик по зелью в окне починки — сразу выпить. У занятых ячеек персонажа — крестик «снять в инвентарь» (кроме серии арены).
- Рюкзак (`src/ui/RucksackModal.ts`) — между боями и в лобби: выпить зелье, взять оружие или артефакт из рюкзака в слот, убрать надетое в рюкзак. В рюкзак теперь кладётся и снаряжение (запасное оружие на серию).
- Пока боец в серии, снаряжение из инвентаря на него не надевается — только из рюкзака.
- Осколки → кубы в «Инвентаре»: 6 осколков = 1 куб (смолы из доки в прототипе нет).
- Допущения прототипа: лут — предмет 1-го уровня без камней; число осколков и скорость починки в лобби — мои.

## Ресурсы

- Куб, Осколок куба, Точильный камень, Чистый пергамент, Ювелирный набор — предметы (`src/data/config/resources.json`), лежат стопками по 100.
- Кубы тратятся на сборку и изменение персонажа прямо из инвентаря; разборка возвращает кубы в инвентарь.
- Осколки — лут с врага; «В кубы» в инвентаре: 6 осколков = 1 куб.
- Точильный камень — прокачка оружия: 3 уровня, ур. 2 — 10 камней, ур. 3 — 25; уровень даёт свойство схемы удара, а не урон (`combat.json → weaponLevels`). Ювелирный набор — ячейка под камень в оружии (до 3, `combat.json → gemCells`). Пергамент — пока заглушка. Описание прокачки — в тултипе оружия под зажатым Alt (`ui/upgradeTip.ts`).
- Сейвы до версии 2 (кубы и осколки были счётчиками) переводятся в предметы при загрузке.
